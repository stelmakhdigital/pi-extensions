# yolo (расширение pi)

Один выключатель для автономного запуска: агент получает максимальные права,
ни стартовый вопрос, ни guard его не останавливают. Нужно там, где в TUI никто
не ответит — Orca-автоматизации, CI, конвейеры, `pi -p`.

## Включение

```bash
pi --yolo "задача"            # или
PI_YOLO=1 pi "задача"         # переменная наследуется дочерними pi
pi --yolo --mode rpc          # работает в любом режиме
```

`PI_YOLO=1` достаточно для Orca: задай переменную в окружении автоматизации и
не трогай команду запуска. Флаг и переменная дают один и тот же режим; флаг
виден в `pi --help`, переменная — в `env`.

## Что выключается

| Источник вопроса/блокировки | В yolo |
|---|---|
| «Trust project folder?» (pi, `project_trust`) | авто-доверие на этот процесс, в `trust.json` ничего не пишется |
| «Доверяешь ли ты проекту?» + изоляция bash (`sandbox`) | расширения нет: вопросов и обёртки bwrap/sandbox-exec |
| «Restart pi inside tmux?» (`subagents`) | вопрос не задаётся, в tmux не переезжаем |
| запросы и блокировки `bash-guard` | нет, включая «пол» катастрофических операций |
| блокировки путей `dir-guard` | нет |
| `edit-fresh` (edit без свежего read) | нет |
| `text-guard` (стиль текста) | нет |
| confirm-гейт браузера (`agents-web-search`) | действия разрешаются автоматически |

Не трогается: `ask_user_question` — вопрос, который модель задала сама,
остаётся вопросом (в headless он и так не имеет UI).

## Как это устроено

`extensions/yolo-mode.ts` — общий хелпер `isYolo()`: `PI_YOLO` или `--yolo` в
argv до разделителя `--` («--yolo» внутри текста промпта режим не включает).
Guard'ы вызывают его в начале factory и рано выходят, поэтому не регистируют
ни обработчиков, ни блоков, ни переключателей. Порядок загрузки расширений не
влияет: проверяется окружение и argv, а не `pi.getFlag`.

Расширение стоит первым в `pi.extensions` — у `project_trust` решение берёт на
себя первый вернувший yes/no обработчик.

## Границы

yolo снимает защиты, которые ты поставил сам, и не трогает изоляцию уровня ОС:
bwrap/Docker/Gondolin по-прежнему решают, что реально доступно процессу. Для
неизвестного кода предпочтителен `--sandbox-level dev` (изоляция без вопросов),
а не yolo.

Состояние guard'ов (`~/.pi/agent/guard-state.json`) в yolo не читается и не
пишется: запущенные обычной сессией `BG OFF`/`DR OFF` переключатели на yolo не
влияют и от yolo не меняются.
