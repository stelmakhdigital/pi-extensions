# todo (расширение pi)

Живой список задач над полем ввода. У pi встроенного todo нет, а для длинного
прогона (yolo, subagents, `pi -p`) без внешнего плана не видно, на чём модель
остановилась.

## Что делает

- Инструмент `todo`: `add` (текст), `toggle` (id), `list`, `clear`. Модель сама
  заводит чек-лист на многошаговой задаче и отмечает шаги (`promptSnippet`
  велит делать это до начала работы и закрывать шаг сразу после него).
- Виджет над редактором: `задачи 2/5`, открытые пункты (не больше 6, дальше
  «… ещё N»), строка «☑ N готово».
- `/todos` и `alt+t` — полный список в оверлее, Escape закрывает. Вне TUI
  (rpc/print) вместо оверлея — обычное уведомление текстом.
- Бейдж `2/5` в футере — когда виджета не видно (его заняло другое расширение,
  либо сессия без TUI).

## Где состояние

В `details` результата инструмента, не в файле (как в bundled
`examples/extensions/todo.ts`). После `/reload`, рестарта и при переходе по
ветке (`session_tree`) список восстанавливается проходом по ветке сессии —
поэтому он корректен для любой ветки, а не переписан глобальным файлом.

К `task.md` и `pi-commander` отношения не имеет: там spec пайплайна (worker →
planner → judge, итерации, ветки), здесь — рабочий чек-лист интерактивной
сессии. Два слоя не синхронизируются сознательно: два источника правды
расходятся на первом же автономном прогоне.

## Границы

- Пункты без сроков и зависимостей: это чек-лист, а не планировщик.
- Виджет живёт в памяти процесса и перерисовывается из истории; если ни одного
  вызова `todo` не было, список пуст — модель обязана завести его сама.

## Тесты

`node test/todo-smoke.test.mjs` — jiti + стаб ExtensionAPI: add/toggle/clear и
их ошибки, кап виджета и свёртка «ещё N», восстановление из ветки на
`session_start`/`session_tree`, поведение без TUI, оверлей и `alt+t`, снятие
виджета на `session_shutdown`.
