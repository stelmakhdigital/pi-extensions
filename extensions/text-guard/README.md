# text-guard (расширение pi)

Контролирует текст, который пишет модель (документация, комментарии к коду,
коммит-сообщения, чат): без эмодзи, стрелок, чек-маркеров, слов-маркеров
ИИ-стиля и «умных названий». Цель — понятный краткий человеческий текст.

## Как работает

Три уровня:

1. **Профилактика** — в системный промпт добавляется секция `<writing-style>`
   (краткие правила стиля: без эмодзи/стрелок, без вводных слов, без
   рекламной лексики). Снимает большую часть проблем до того, как текст написан.
2. **Контроль записи** — перехват `write` / `edit` / `bash`:
   - `write.content` и `edit.newText` сканируются целиком (по типу файла:
     markdown — полностью, код — только комментарии);
   - в bash извлекаются текстовые фрагменты: сообщения `git commit -m`
     (и `gh pr/issue create --title/--body`), содержимое heredoc
     (`cat/tee … > file <<EOF`), `echo/printf … > file`.
   - в режиме strict вызов блокируется с конкретной причиной (какие маркеры,
     в каких строках) — модель переписывает сама;
   - механически исправимое (эмодзи/стрелки/чек-маркеры) при включённом
     автофиксе (`/text-guard:fix`) правится мутацией ввода in place,
     без блокировки.
3. **Мониторинг чата** — `message_end` считает маркеры в ответах модели
   (блокировать текст чата нельзя). Счётчик появляется бейджем в футере
   (`TG <N>`) и в статистике.

## Режимы

- **warn (по умолчанию)** — маркеры считаются, показывается предупреждение
  (не чаще раза в 15 с), текст записывается без блокировки.
- **strict** — запись текста с маркерами блокируется с конкретной причиной.
- **off** — ничего не проверяется, секция стиля из промпта убирается.

Переключение: `/text-guard` (off → warn → strict). Режим персистентен
(`~/.pi/agent/guard-state.json`, переживает `/reload` и `pi -c`; новая сессия
стартует с warn). Флаги: `--text-guard-strict`, `--text-guard-off`.

В субагентах (`PI_SUBAGENT_DEPTH >= 1`) — fail-safe: strict, состояние
guard-state не читается, UI нет (блок — с причиной, модель субагента перепишет).

## Что проверяется

| Категория | Примеры | Где |
|---|---|---|
| `symbols` | эмодзи (🚀 🎉), стрелки (→ ⇒ ➜), чек-маркеры (✓ ✔ ✅), ⭐ ⚠️ | везде |
| `words-ru` | «давайте», «итак», «простыми словами», «на самом деле», «стоит отметить», «важно понимать», «подводя итог», «в целом», «кстати», «надеюсь», «с удовольствием», «конечно!» | везде |
| `words-en` | delve, moreover, furthermore, leverage, seamless, robust, comprehensive, cutting-edge, elevate, journey, realm, showcase, let's, sure!, great!, in conclusion, tl;dr | везде |
| `naming` | wizard, magic, awesome, ultimate, ninja, rockstar, магия, волшебный | только заголовки документов и коммиты |
| `structure` | жирная метка в каждом буллете (`**Note:** …`) | только markdown |

Категории настраиваются в конфиге (см. ниже): можно выключать (`categories`)
и добавлять свои слова (`words`).

## Настройка — `.text-guard.json` в корне проекта

```json
{
	"allow": ["README*", "docs/legacy/**"],
	"skip": ["**/fixtures/**"],
	"words": ["своё слово"],
	"ignore": ["robust", "journey"],
	"categories": ["symbols", "words-ru", "words-en", "naming", "structure"]
}
```

- `allow` — пути, которые не сканируем вовсе (глобы: `**`, `*`, `?`);
- `skip` — добавить к встроенному списку (`**/*.json`, `**/*.lock`, `**/*.svg`,
  `**/*.snap`, `**/*.min.*`, lock-файлы, картинки, `node_modules`, `.git`…);
- `words` — свои слова-маркеры (RU/EN, без ограничений);
- `ignore` — слова/токены, исключённые из всех списков (борьба с ложными
  срабатываниями, например `robust` в техническом смысле);
- `categories` — включённые категории (по умолчанию все).

Невалидный JSON игнорируется с предупреждением.

## Команды и флаги

- `/text-guard` — переключить режим off → warn → strict (персистентно);
- `/text-guard:fix` — переключить автофикс эмодзи/стрелок (действует в strict);
- `/text-guard:stats` — статистика за сессию: категории, топ маркеров
  (удобно для тюнинга списков);
- `--text-guard-strict` / `--text-guard-off` — стартовый режим;
- бейдж в футере: `TG OFF`, `TG STRICT`, `TG <N>` (находок в чате при warn).

## Границы (сознательные компромиссы)

- **Строки внутри кода не сканируются** — только комментарии (эвристика по
  началу строки: `//`, `/*`, `#`). Строки vs комментарии надёжно не различить
  простыми средствами; эмодзи в легитимных строках (тесты, UI-копирайт)
  закрываются allow-глобами.
- **Переписывания через LLM нет** — блок с конкретной причиной дешевле и
  детерминированнее: модель исправляет за одну попытку.
- **Защита от петли**: если сигнатура текста заблокирована дважды за 5 минут
  и модель не исправила, вызов пропускается с одноразовым предупреждением
  пользователю.
- Bash-парсинг эвристический (не полный shell-парсинг): сложные кавычки и
  подстановки могут уйти мимо скана — это контроль стиля, а не безопасность.
- Коммиты проверяются при создании (`git commit -m`); правка старых коммитов
  через rebase не сканируется.
