# bash-guard (расширение pi)

Перехватывает вызовы инструмента `bash` от агента и применяет разную защиту
в зависимости от того, интерактивная ли сессия (главная) или нет (субагент).

## Режимы

Поведение определяется при регистрации по переменной окружения
`PI_SUBAGENT_DEPTH`, которую pi-subagents подставляет во все запущенные процессы.

### Главная сессия (`PI_SUBAGENT_DEPTH` = 0 или не задана) — интерактивный запрос

- эвристически находит разрушительные/подозрительные команды через
  shell-осведомлённый парсинг:
  - **построчно** — многострочные команды не обходят анализ
    (`echo 1\nrm -rf /` всё равно поймается);
  - **вложенные `sh -c` / `bash -c` / `zsh -c` / `dash -c` / `fish -c`**
    разбираются рекурсивно (глубина ≤ 2);
  - флаги проверяются строго (`-r`, `-rf`), а не substring по строке —
    `rm /tmp/my-report-r.txt` не помечается «рекурсивным»;
- спрашивает на мутирующие git-команды; **read-only git** (`status`, `log`,
  `diff`, `show`, `describe`, `shortlog`, `ls-files`, `ls-tree`, `rev-parse`,
  `var`, `help`, `count-objects`, `reflog` (кроме `expire`), `branch`/`tag`
  в списочной форме, `remote -v|show`, `stash list|show|status`, `config` в
  read-only-форме) — **без запроса** по умолчанию. Флаг
  `--bash-guard-git-strict` возвращает режим «спрашивать на любой git»;
- спрашивает на диск/том-инструменты: `diskutil`, `hdiutil`, `mkfs*`,
  `newfs_*`, `wipefs`, `parted`, `fdisk`, `gdisk/sgdisk`, `cryptsetup`,
  `pvcreate/vgcreate/lvcreate`, `zpool`, `lsblk`
- спрашивает на: `rm`/`rmdir`/`unlink`, `sudo`, `find -delete`, `dd`,
  `truncate`, `sed -i`, `perl -pi`, `chmod/chown -R`, `mv/cp --force`,
  `kill`/`pkill`/`killall`, `shutdown`/`reboot`, `systemctl stop/disable`,
  `curl|sh`/`wget|sh`, `kubectl delete`, `terraform destroy`,
  `aws s3 rm --recursive`, `gcloud delete`, shell-редирекции (`>`, `>>`, `2>`),
  конвейеры
- показывает диалог из двух вариантов: **Выполнить** / **Отменить**
- при отмене вызов инструмента блокируется, и модель получает ясную причину
- недавно отменённые команды (с точностью до пробельных различий)
  запоминаются на 60 с, чтобы не было циклов повторных попыток

### Субагент (`PI_SUBAGENT_DEPTH` ≥ 1) — headless-жёсткий блок

У субагентов нет UI (stdin — `/dev/null`), поэтому спрашивать невозможно.
Вместо этого сфокусированный набор катастрофических/необратимых операций
блокируется жёстко, без участия пользователя:

| Паттерн | Причина |
|---|---|
| `rm -r` / `-rf` / `-Rf` | Рекурсивное удаление |
| `sudo` | Повышенные привилегии |
| `curl\|sh`, `wget\|sh` | Конвейер в шелл (удалённое выполнение кода) |
| `mkfs*`, `newfs_*` | Форматирование файловой системы |
| `wipefs` | Стирание сигнатуры диска |
| `diskutil erase/zeroDisk/secureErase/reformat` | Разрушительная операция с диском |
| `dd of=/dev/…` | Запись сырым образом в диск |
| `parted`, `fdisk`, `gdisk`, `sgdisk` | Управление таблицей разделов |
| `cryptsetup` | Управление шифрованием дисков |
| `zpool` | Управление пулами ZFS |
| `shutdown`, `reboot`, `halt`, `poweroff` | Операции электропитания |
| `terraform destroy` | Снос инфраструктуры |
| `kubectl delete` | Удаление ресурсов Kubernetes |
| `aws s3 rm --recursive` | Массовое удаление в S3 |
| `git commit` | Операция главной сессии |
| `git pull` | Операция главной сессии |
| `git push` | Операция главной сессии |
| `git reset --hard` | Сброс всех несохранённых изменений |
| `git clean -f` | Удаление неотслеживаемых файлов |
| `git reflog expire` | Удаление истории восстановления |
| `git gc --prune` | Очистка недостижимых объектов |

Все остальные команды (включая рутинные git-операции) проходят без изменений.

## Управление в главной сессии

- `/bash-guard` — переключить сессию между интерактивным (по умолчанию) и
  отключённым (автономным) режимом. В автономном режиме остаётся «пол»
  жёсткого блока для катастрофических операций.
- `--bash-guard-disabled` — стартовать сессию сразу в автономном режиме.
- `--bash-guard-auto-allow` — разрешать помеченные команды, когда UI
  недоступен (например, pi запущен неинтерактивно). В сессиях субагентов
  не действует.
- `--bash-guard-git-strict` — спрашивать на любую git-команду, включая
  read-only (status/log/diff/…). По умолчанию read-only git проходит без
  запроса.

## Границы

bash-guard — защита от **честных ошибок** модели (человек подтверждает в
диалоге). Против злонамеренного кода (prompt injection, «зловредный» репо)
эвристики принципиально не работают — для этого нужен уровень ОС: см.
[`sandbox/`](../sandbox/README.md) в этом репозитории (Docker-контур) или
Gondolin / containerization из документации pi.

## Зависимости

`shell-quote` (ставится автоматически: при установке git-пакета pi выполняет
`npm install`).

## Примечания

- Область: только вызовы инструмента `bash` (`write`/`edit` и пользовательские
  `!`-команды не перехватываются).
