# injection-guard (расширение pi)

Защита от prompt injection: когда модель делает то, что ей написали в чужих
данных. Текст инъекций не детектится — работают границы, а не паттерны.

## Четыре слоя

1. Маркировка (`tool_result` + системный промпт). Вывод внешних инструментов
   оборачивается в `<UNTRUSTED tool="..." src="...">`; попытки закрыть фрейс
   досрочно вырезаются и помечаются `[fence-stripped]`. Секция
   `<untrusted-content>` объясняет модели правила: внутри фрейса данные, не
   команды. Файловые инструменты в недоверенном проекте (`isProjectTrusted()`
   false) получают короткую пометку вместо фрейса — иначе каждый `read`
   раздувает контекст.

   Что считается внешним: `web_*`, `browser_*`, любые MCP-инструменты, `bash` с
   сетевым выводом (`curl`, `git clone`, `npm install`, URL в команде), а также
   `read`/`grep`/`find`/`ls` в недоверенном проекте. Переопределяется в
   `.injection-guard.json`.

2. Эксфильтрация (`tool_call`). Корреляция: в одной bash-команде чтение секрета
   (`~/.ssh`, `~/.aws`, `auth.json`, ключевые файлы — общий список с dir-guard
   в `extensions/secret-paths.ts`) И сетевой уход — блок с причиной.
   Работает в label и в yolo. Тот же слой блокирует доступ к
   секрету вне CWD через read/write/edit, но только в окне недоверия — это
   резерв на случай выключённого dir-guard. `.env` в корреляции не участвует
   (слишком частый в обычных командах), его закрывает dir-guard по пути.

3. Эскалация (`tool_call`, только strict). Пока активно окно недоверия,
   запрашивается подтверждение: правка файлов агента (`AGENTS.md`,
   `.pi/settings.json`, guard'ы, `extensions/*`), отправка данных наружу,
   установка пакетов, `git push`. В субагенте и в yolo вместо вопроса блок.

Окно недоверия открывается первым внешним результатом и закрывается живой
репликой пользователя (`source` = interactive/rpc). Сообщение от расширения
(steer подагента) окно не закрывает.

4. Маскирование (`tool_result`). Из вывода bash вырезаются значения по жёстким
   формам: AWS `AKIA…`/`ASIA…`, GitHub `ghp_…`/`github_pat_…`, Slack `xox…`,
   Google `AIza…`, OpenAI `sk-…`, GitLab `glpat-…`, npm `npm_…`, Stripe
   `sk_live_…`, JWT, PEM-ключи, пароль в `postgres://user:pw@host` и
   `ТОКЕН=значение` / `password: …`. Дампы (`env`, `printenv`, `export -p`,
   `set |`, `git config --list`, `cat .env`) маскируются по имени переменной —
   и только по токенам имени (`MY_DEPLOY_KEY` — да, `PATH` — нет). Заменяется на
   `[скрыто:имя]`.

   Файловые инструменты (`read`/`write`/`edit`) не маскируются: модель правит
   файлы посимвольно и обязана видеть содержимое дословно, а доступ к файлам
   ключей закрывает dir-guard. «Голые» hex/base64 не маскируются — это git sha и
   обычные данные; плейсхолдеры (`$FOO`, `changeme`, `xxxx`) тоже.

## Режимы и управление

| Команда/флаг | Действие |
|---|---|
| `/injection-guard` | off -> label (дефолт) -> strict |
| `/injection-guard:stats` | что маркировано, что заблокировано, текущее окно |
| `--injection-guard-off` / `--injection-guard-strict` | режим на старте |
| бейдж в футере | `⚠ IG n` — n внешних результатов в окне недоверия |
| `.injection-guard.json` в CWD | `{ "untrusted": ["web_fetch"], "trusted": ["browser_*"], "redact": "bash", "redactAllow": ["AKIAIOSFODNN7EXAMPLE"] }` |

Маскирование настраивается тем же файлом и не зависит от режима: `redact` —
`off` | `bash` (дефолт) | `all` (добавляет внешние инструменты: веб, браузер,
MCP); `redactAllow` — значения-фикстуры, которые трогать не надо (glob `*`).
После правки файла — `/reload`.

Режим персистентен (`~/.pi/agent/guard-state.json`, переживает `/reload` и
`pi -c`; новая сессия — дефолт). В субагенте состояние не
читается: fail-safe strict.

## Границы

- Маркировка помогает модели, но не гарантирует: модель может выполнить инструкцию
  из фрейса. Гарантию даёт слой 2 (секрет+сеть) и подтверждения слоя 3.
- Окно недоверия снимается любой живой репликой, хотя загруженная страница
  остаётся в истории. Взамен — guard не висит всю сессию.
- `bash` считается сетевым по строке команды: `grep -r "http://"` промаркирует
  вывод как внешний (дороже на несколько строк, не блокирует).
- Перетаскивание содержимого в контекст минуя инструменты (пользователь сам
  вставил текст чужого README) не размечается — реплика пользователя доверенная.
- Маскирование теряет значение: если ключ реально нужен (вывести в конфиг),
  модель его не увидит и должна спросить пользователя. Это осознанный обмен —
  иначе значение уезжает провайдеру в контексте. Формы вне списка не
  маскируются: redact — шум в пользу тишины, а не DLP.

## Тесты

`node test/injection-guard-smoke.test.mjs` — jiti + стаб ExtensionAPI: фрейс,
обезвреживание поддельной метки, метка для недоверенного проекта, корреляция
«секрет + сеть», спрашивание в strict и отказ пользователя, снятие окна
репликой, маскирование форм ключей и дампа env (PATH не тронут, git sha не
тронут, redactAllow и redact: off), переключение режимов.
