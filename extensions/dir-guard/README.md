# dir-guard (расширение pi)

Жёстко блокирует вызовы инструментов `read`/`write`/`edit`/`bash`, чьи пути
уходят **вне рабочей директории сессии (CWD)** и её allowlist'а. Агент не может
читать, писать или исследовать файлы за пределами текущего проекта — без
интерактивного промпта: вызов возвращается с `block: true` и человекочитаемой
причиной (`dir-guard: путь /etc/passwd (→ /etc/passwd) вне рабочей директории …`).

## Механика

- **CWD** берётся из `ExtensionContext` (`ctx.cwd`) и канонизируется
  (**realpath**) **один раз на сессию** — CWD pin'ится, на каждый tool call не
  пересчитывается.
- **read/write/edit**: путь из `input.path`. Относительный разрешается против
  CWD, затем путь канонизируется: для существующего — `realpath`; для
  несуществующего — `realpath` ближайшего существующего предка + дописанный
  хвост. Разрешён, если canonical-форма внутри CWD или внутри allowlist-корня.
- **bash**: эвристика, **НЕ полный shell-парсинг**. Из команды извлекаются
  path-подобные токены:
  - абсолютные пути (`/etc/passwd`, включая мульти-сегментные) — кроме хвостов
    URL (`https://host/…`);
  - `~/…` (и сам `~`);
  - относительные токены с `..` (из относительного пути выйти выше CWD можно
    только через них: `cat ../../../etc/passwd`).

  Каждый токен проверяется теми же правилами (realpath + CWD/allowlist).
  Токены внутри CWD не блокируются.

- **Symlink-escape блокируется ВСЕГДА**: проверка идёт по canonical (realpath)
  пути, а не по строковому виду. Ссылка внутри CWD, указывающая наружу,
  разрешается в реальный внешний путь и блокируется — даже если строковый вид
  пути есть в allowlist, и даже если конечный файл ещё не существует.

## Что НЕ блокируется (честные границы)

- **Неразрешимые токены в bash**: `$VAR`, `$HOME/file`, `*`-глобы, обратные
  кавычки — пропускаются (shell их разовьёт в runtime). Это **осознанный
  компромисс**: строгий блок всех `$VAR` утонул бы в ложных срабатываниях.
  Команда `cat $HOME/secret` проходит; защита на этот случай —
  [`sandbox/`](../sandbox/README.md) (изоляция на уровне ОС).
- Bash-эвристика работает по токенам: экзотический shell (процесс-подстановка
  в имени файла и т.п.) может дать пропуск.
- Инструменты, отличные от `read`/`write`/`edit`/`bash` (grep, find, ls,
  кастомные) не перехватываются.
- Защита от **честных ошибок** модели, не от злонамеренного кода
  (prompt injection) — см. [`sandbox/`](../sandbox/README.md).

## Allowlist

Список **корневых директорий**: разрешены сам путь и всё в нём. Все allowlist-
пути канонизируются (realpath) при старте сессии.

| Источник | Пример |
|---|---|
| Встроенный дефолт (всегда) | `$HOME/.pi` (конфиги скиллов/агентов pi) |
| CLI-флаг `--dir-guard-allow` | `--dir-guard-allow ~/notes,/opt/reference` (список через запятую; `~` разрешается; повторный флаг не суммируется — парсер флагов pi хранит одиночные значения, поэтому несколько путей задаются одним коммат-списком) |
| Файл `.dir-guard.json` в CWD | `{"allow": ["~/notes", "/opt/reference"]}` |

`.dir-guard.json` читается при старте сессии; невалидный JSON — warning через
уведомление и игнор файла (блокировки продолжают действовать).

## Управление

- `/dir-guard` — переключить guard **на эту сессию** (in-memory, не
  персистент). При отключении в футере появляется бейдж ` ⚠ DR OFF `
  (фон toolErrorBg) — его видимость = guard выключен.
- `--dir-guard-disabled` — стартовать сессию сразу с выключенным guard
  (бейдж `DR OFF` показывается при `session_start` с `reason: startup`).
- Субагент (`PI_SUBAGENT_DEPTH >= 1`): те же правила, жёсткий блок, без UI,
  команд и бейджа.
