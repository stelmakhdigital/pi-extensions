# Экран с данными: таблицы, графики, метрики

Читать этот файл, когда экран — данные (таблица, график, метрики, админка, список), а не лендинг или маркетинговая страница. Токены, палитра и типографика — в `SKILL.md` рядом, проверка готового экрана — в `../ui-review/SKILL.md`.

Экран с данными оценивается по одному критерию: за сколько секунд находится ответ на вопрос. Красота вторична, плотность и сравнимость первичны.

## Шаг 1 — вопрос, на который экран отвечает

Одна строка перед сборкой: «кто и какой вопрос задаёт этому экрану» («куда ушёл бюджет в этом месяце», «какие сервисы деградируют»). Экран, где на этот вопрос отвечает один блок, а не двенадцать карточек с цифрами, — уже половина результата. Если в проекте есть `DESIGN.md`, токены и шкала отступов берутся оттуда; отдельно фиксируется шкала размера цифр (см. «Числа читаются»).

Если тип графика не выводится из вопроса — на экране лишний график, а не недостающий.

| Что нужно узнать | Форма | Не делать | Когда тип вообще работает |
|---|---|---|---|
| Как менялось во времени | линейный график, 1-3 серии | области с прозрачной заливкой на 5 сериях | >= 5 точек, известна единица, серии сопоставимы |
| Сколько величин между собой | бары | 20 категорий на одном поле | <= 12 категорий, иначе топ-N + «прочее» |
| Кто первый, рейтинг | горизонтальные бары, сортировка по значению | вертикальные бары с подписями под 45° | подписи влезают без поворота |
| Сколько сейчас, важно сравнение с прошлым | крупная цифра + дельта + спарклайн | круговая диаграмма | одно значение; сравнение — второй цифрой рядом |
| Из чего состоит сумма | stacked bar горизонтально или таблица с долями | pie на 9 секторов | <= 5 сегментов; pie только на 2-3 |
| Изменение во времени по категориям | small multiples | 6 серий на одном поле | 2-4 серии на поле |
| Распределение | гистограмма или box plot | среднее без разброса | >= 30 наблюдений |
| Зависимость двух величин | scatter с регрессией, если она есть | две таблицы рядом | >= 20 точек, есть смысл в корреляции |
| Величины по категориям и времени | heatmap с легендой-шкалой | таблица 20x30 | ось категории x ось времени |
| Состав по категориям + числа | таблица с условным оформлением ячеек | график без таблицы, когда числа сравниваются построчно | — |
| Где (карта) | карта только если география меняет решение | карта ради красоты | — |

## Шаг 2 — данные прежде макета

Верстать на надутых и на вырожденных данных, обе проверки до сдачи:

- Надутые: имя 40+ символов, число `1 284 903,57 ₽`, дата с таймзоной, 5 000 строк в таблице, 1280/768/375.
- Вырожденные: 0 строк, 1 точка на графике, все нули, отрицательные значения, один спайк на порядок выше остальных, пропуски в середине ряда, значения без прав доступа (`—`, не `0`).

Каждая вырожденная ситуация имеет названное поведение (таблица ниже), иначе экран разваливается на первом же реальном запросе.

## Оси, сетка, форматтеры

- Линейная шкала по умолчанию. Логарифмическая — только с подписью «шкала логарифмическая».
- Частоты, доли и деньги: ноль на шкале. Обрезка без подписи искажает сравнение; у денежной шкалы ноль обязателен, когда сравниваются величины, иначе обрезку подписать.
- Сетка горизонтальная, светлая, не чаще 5 линий; вертикальная сетка по точкам времени не нужна.
- Подписи оси Y в тех же единицах, что и заголовок, один раз: `₽ млн`, а не `1 000 000 000`. Метки на 2-3 меньше, чем позволяют пиксели: подписи осей не конкурируют с линиями.
- Временная ось: интервал между метками кратный данным (сутки/неделя/месяц), последняя точка подписана, если она важна.
- Подписи осей контрастны 4.5:1 и не меньше 11-12 px: экономия на подписях отнимает у графика смысл.

```js
const nf = (opts) => new Intl.NumberFormat("ru-RU", opts);
const money = (v) => nf({ style: "currency", currency: "RUB", maximumFractionDigits: 0 }).format(v);
const num = (v) => nf({ maximumFractionDigits: 0 }).format(v);            // 1 284 903
const pct = (v) => nf({ style: "percent", maximumFractionDigits: 1 }).format(v);
const compact = (v) => nf({ notation: "compact", maximumFractionDigits: 1 }).format(v);  // 1,3 млн
const date = (d) => new Intl.DateTimeFormat("ru-RU", { day: "2-digit", month: "short" }).format(d);
const delta = (v) => `${v > 0 ? "+" : v < 0 ? "−" : "±"}${pct(Math.abs(v))}`;  // знак и направление текстом
```

## Числа читаются, а не выглядят

- Разделители тысяч и десятичный знак — по локали пользователя, а не хардкодом.
- Валюта и единица один раз на блок: в заголовке карточки или в подписи оси, но не в каждой ячейке.
- Компакт (`1,2 млн`) допустим в заголовке карточки и в подписи оси; в таблице — точное значение.
- Дельта со знаком и направлением: `+12%` и стрелка (или цвет) плюс текст для скринридера: `<span aria-hidden="true">▲</span><span class="sr-only">рост на</span> 12%`. Цвет один смысл не несёт — красный и зелёный не различаются при дальтонизме.
- Пропуск — `—` с подсказкой или `нет данных`, но не `0` и не пустая ячейка: пустая читается как ноль.
- Дата с таймзоной, если данные из разных зон: `14:03 MSK`.
- Один формат на колонку. `12,5` рядом с `12,50` и `12` в одной колонке читается как ошибка данных.
- Цвет: один акцент на ряд, последовательная шкала для величины, расходящаяся для «вокруг нуля». Радуга и 8 цветов легенды — признак, что ряды не разобраны.

## Responsive SVG без библиотек

Библиотека графиков уже есть в проекте — дописываем в неё; свои оси, масштаб и хит-зоны заводим только когда библиотеки нет или её вес не оправдан (одна диаграмма на экран). Ниже — минимум, нужный в любом случае: доступное имя, немасштабируемая толщина линии и подписи фиксированным кеглем.

```html
<svg viewBox="0 0 600 240" preserveAspectRatio="none" role="img" aria-labelledby="chart-title">
  <title id="chart-title">Выручка по неделям, ₽ млн</title>
  <g class="grid">…</g>
  <polyline class="series" points="…" fill="none" stroke="currentColor" stroke-width="2" vector-effect="non-scaling-stroke" />
</svg>
```

- `viewBox` + `width:100%`; толщина линии через `vector-effect: non-scaling-stroke`, иначе на мобильном линия жирная или тонкая.
- Подписи осей не масштабировать вместе с полотном: рисовать их отдельным слоем с фиксированным кеглем либо опускать часть меток при узком вьюпорте.
- `role="img"` + `<title>` — иначе скринридер объявляет безымянную картинку. Если график несёт данные, рядом обязательна таблица-альтернатива (`<table class="sr-only">` или раскрывающийся блок «данные графика»).
- Точки, на которые можно навестись, доступны с клавиатуры: `tabindex="0"` на маркере либо управление «стрелки влево/вправо по точкам» с объявлением значения в `aria-live`.

## Вырожденные данные: названное поведение

| Случай | Что делаем |
|---|---|
| 0 строк в таблице | Блок «пусто»: почему пусто и что сделать (изменить период, импортировать). Скелетон не показывать. |
| 1 точка на графике | Точка + число, линия не рисуется; подпись «недостаточно данных для тренда». |
| Все нули | Шкала не сжимается до одной линии: фиксированный диапазон 0-1 с подписью. |
| Отрицательные значения | Нулевая линия явная и подписанная, области ниже нуля не красить в «ошибку» без причины. |
| Один спайк на порядок выше остальных | Ось не растягивать до спайка: клиппинг с маркером «пик N вне шкалы» или log-шкала с подписью. |
| Пропуск в середине ряда | Разрыв линии, а не прямая через дыру; подсказка «данных за 12.03 нет». |
| Нет прав на значения | `—` с подсказкой; график либо без этой серии, либо с явной подписью «часть данных скрыта». |
| Значения расходятся в двух источниках | Показывать источник и время среза у цифры, а не самое удобное число. |

## Состояния и плотность

- Состояния на каждый блок данных: загрузка (скелетон тех же размеров), пусто (что делать, а не «нет данных»), ошибка (причина + повтор), частично (половина серий не пришла — сказать, а не рисовать неполный график как истину), нет прав (`—` с объяснением).
- Скелетон повторяет геометрию итогового блока (те же высоты и ширины) — иначе каждая загрузка даёт CLS, это видно в `../../ui-review/scripts/perf.mjs`.
- Частичная загрузка хуже честной ошибки: блок, где пришла половина рядов, обязан сказать об этом.
- Повтор ошибки — кнопкой с тем же действием и сохранёнными фильтрами, а не перезагрузкой страницы.
- Таблица: липкая шапка при скролле корпуса, сортировка с `aria-sort`, нумерация и «показано X из Y», строчка-детали на клик, горизонтальный скролл корпуса вместо сплющивания колонок.
- Таблица на тысячи строк: виртуализация или страница по 50-100 со счётчиком, который не врёт при фильтре.
- Фильтры и выбранный период — в URL: экран должен открываться по ссылке и переживать перезагрузку.
- Плотность: цифры выравниваются по правому краю, текст по левому; вертикальные разделители между колонками не нужны, когда есть выравнивание.
- Автообновление: показывать «обновлено 14:03» и паузу на ховере, иначе сравнение двух чисел из разных моментов времени врёт.

## Шаг 3 — проверка

- Первый вопрос «где главное» решается за один взгляд; если для этого нужно сканировать 12 карточек — иерархия не собрана.
- Все ли числа в колонке в одном формате; все ли отрицательные видны как отрицательные.
- Легенда рядом с полем, а не сверху через весь экран; порядок серий в легенде равен порядку на графике.
- `a11y.mjs <url> --out DIR` на 375/768/1440 надутыми данными: разделы про переполнение, тесные цели, `aria-sort` и картинки. Скриншоты показать, а не описать.
- `perf.mjs <url> --wait 1500` — на списке в тысячу строк типичны длинные задачи; `TBT > 200 мс` = виртуализировать или резать на страницы.
- Миниатюрой (375px) проверить, не превратился ли график в кашу: на мобильном правильны один-два показателя и таблица, чем шесть графиков; горизонтальный скролл остаётся только у корпуса таблицы.
- Проверить чтение вслух: зачитать заголовок карточки и значение скринридером — из `+12%` и `—` должно быть понятно направление и смысл пропуска.
