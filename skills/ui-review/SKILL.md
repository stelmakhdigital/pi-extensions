# UI Review

Отчёт — только находки, с доказательством и исправлением. Правила чеклиста пользователю не пересказывать. Экран собирается с нуля — порядок сборки в `../ui-design/SKILL.md`.

Три правила держат всё остальное:

1. **Не называть цифру, которую не измерил.** «Контраст 4.6:1», «проходит WCAG», «нарушений нет» — только из вывода скрипта. Не мерил — пиши «не проверено».
2. **Skip это не pass.** Скрипт без браузера или без axe ничего не проверил: коды выхода 3 и 4 означают «среды нет», и в отчёте это отдельная строка «не проверено», а не зелёный результат.
3. **Рендер и глазами.** Зелёные проверки уживаются с visibly сломанным экраном: скриншоты смотреть, а не только вывод.

## Шаг 0 — контекст и данные

1. Если в проекте есть `DESIGN.md`, читать его первым: отклонение от токенов = находка, а не «вариант».
2. Наполнить поля данными до проверки. На пустой модели переполнение, обрезка и пустые состояния не видны ничем. Минимум: имя 40+ символов, домен/email 30+, число с разделителями и валютой, дата с таймзоной, одно пустое поле, список из 0 / 1 / 12 записей. Наполнить нечем (нет моков, нет бэкенда) — сказать в отчёте и пометить раздел «Данные» непроверенным.
3. Открыть то, что по умолчанию скрыто: `--click` (модалка, дропдаун, раскрытие), нужные состояния приложения или вручную. Ревью первого экрана без модалки — не ревью.
4. Дев-сервер не поднят — подними сам (`npm run dev` в фоне) и не убивай до конца ревью. Экран не открыт — раздел помечается «не проверено», а не пропускается молча.

## Шаг 1 — машинная проверка

```bash
# S — каталог этого скилла (pi сообщает путь к SKILL.md при загрузке), запускать из корня проверяемого проекта
S=<каталог скилла ui-review>

node "$S/scripts/lint-ui.mjs" src --strict          # 1) по исходникам, без браузера
node "$S/scripts/a11y.mjs" http://localhost:3000 \  # 2) по отрендеренному экрану
  --widths 375,768,1440 --out ui-review/run-1 --wait 800
node "$S/scripts/a11y.mjs" http://localhost:3000 \  # 3) тёмная тема и reduced-motion отдельными прогонами
  --widths 375,768,1440 --out ui-review/run-dark --dark --wait 800
node "$S/scripts/a11y.mjs" http://localhost:3000 \
  --widths 1440 --out ui-review/run-rm --reduced-motion --wait 800
```

Экран тяжёлый (картинки, список, сторонние скрипты) или пользователь жалуется на скорость — в том же каталоге `scripts/` лежит `perf.mjs` (LCP/CLS/INP/TBT, вес по типам, кто двигает макет): порядок работы с ним в шаге 3 и в `references/perf.md`.

Полезные флаги `a11y.mjs`: `--click "button.open-menu,button.new-item"` (модалка/меню), `--dark` (emulateMedia `color-scheme: dark`: контраст пересчитывается по тёмным цветам, скриншоты уходят в `<width>-dark.png`), `--reduced-motion` (проверяет, что под `prefers-reduced-motion: reduce` текст не остался с `opacity: 0` — такой прогон валится с exit 1), `--zoom 2` (CSS `zoom`, ловит обрезку при крупном тексте), `--baseline ui-review/run-1` (регрессия к прошлому прогону), `--diff-threshold 0.2`, `--strict` и `--json` для CI, `--axe ./node_modules/axe-core/axe.min.js` для офлайна, `file://` для статичного HTML. Один раз на проверяемый проект: `npm i -D playwright && npx playwright install chromium`; пакет ищется от каталога запуска, поэтому запускать из корня проекта.

Что ловит `a11y.mjs`: нарушения axe (роли, имена, landmarks, `meta viewport`, `aria-*` не на тех элементах), собственный расчёт контраста по WCAG (включая состояния, где axe молчит, с явным счётом пропущенного), горизонтальный скролл и элемент шире вьюпорта, шрифт < 12px, цели клика < 24px, `transition: all`, `will-change`, отсутствие `prefers-reduced-motion`/`prefers-contrast`, `<html lang>`, `user-scalable=no`, незагруженные картинки, ссылки без назначения, `z-index > 1000`, медиа без размеров, состояние веб-шрифтов.

Что ловит `lint-ui.mjs` (кода, не рендера): маскировка переполнения через `overflow-x: hidden` на корне, `100vw`, `!important` на размерах, убранный focus outline, подставной текст и TODO, generic CTA, emoji вместо иконок, градиенты и часть «признаков генерации» из `../ui-design/references/anti-patterns.md` (правила заложены в скрипте отдельно от этого списка), шрифты и стили с чужого CDN, `@keyframes` без `prefers-reduced-motion`, вставка HTML строкой. Конкретное правило снимается комментарием `// ui-lint-disable <id>`, целиком правило — `--rule-allow <id>`.

Чего оба не ловят (для этого шаги 2 и 4): корректность `aria-current`/`aria-expanded`, порядок обхода и ловушка фокуса, переполнение внутри открытой модалки, иерархия, плотность, выравнивание, пустые и ошибочные состояния, отклонение от `DESIGN.md`.

`--baseline` даёт побитовое сравнение: процент и число изменившихся пикселей плюс `<width>-diff.png` с красной разметкой. Прочитать diff-кадр и разобрать, что изменилось; «изменилось 3%» без разбора — не находка. Разные размеры кадров не сравниваются (поменялась высота документа или вьюпорт) — это отдельная находка.

## Шаг 2 — рендер и глазами

Смотреть `ui-review/run-N/<width>.png`, а не живой браузер: скриншот фиксирует то, что потом уедет из контекста. Плюс прокликать: у контрола, который ничего не меняет, находка.

1. Что первое бросается в глаза и совпадает ли это с главным действием экрана.
2. Где текст режет, прилипает к соседнему блоку или встал в одну строку на весь экран.
3. Где блок неопределённой ширины/высоты сядет на сосед при 12 записях вместо 3.
4. Держится ли один визуальный язык (радиусы, тени, отступы, веса) или каждый блок сам по себе.
5. Обе темы, зум 200% и ширина 280px: не на чём экономить. Тема, `prefers-reduced-motion` и `zoom` включаются флагами `a11y.mjs` (шаг 1), руками остаётся только то, чего машина не видит: качество иконок, уместность цвета, чтение экрана целиком.

## Шаг 3 — скорость

Мерять, когда экран тяжёлый, когда пользователь жалуется на тормоза и всегда, если правкой тронули загрузку. Ядро одно: `perf.mjs <url> --click "<действие>" --wait 1500`, правка, повторный замер теми же флагами; правка, не улучшившая метрику за пределами шума, откатывается. Порядок правок по признакам из вывода, пороги CWV, лаборатория против RUM и бюджет в CI — `references/perf.md`.

## Шаг 4 — чеклист и отчёт

Разделы чеклиста (что именно смотреть): `references/checklist.md`; поведение самодельных виджетов (модалка, комбобокс, табы, меню, live-объявления) — `references/aria-patterns.md`; признаки генерации, с которыми сверяем новый дизайн, — `../ui-design/references/anti-patterns.md`; ревью кода экранов, а не только рендера (стейт, эффекты, ключи, формы, цикл рендера, вес импортов) — `references/code.md`, находки отсюда идут в тот же отчёт с файлом и строкой. Тяжесть: `blocker` (ломает использование или недоступно), `major` (портит экран заметно), `minor` (косметика).

```
src/InvoiceTable.tsx:118 — blocker — ячейка суммы вылезает за вьюпорт на 375: у td нет min-width: 0
DOM button.icon (375px) — major — цель 20x20px, поднять до 44px псевдоэлементом
ui-review/run-1/768.png — minor — заголовок карточки прилип к бейджу, добавить gap 8px
не проверено: тёмная тема, состояние ошибки загрузки (нет мока)
```

Селекторы из браузера помечать `DOM ...` с шириной; причина в коде — указывать файл и строку. Формулировка обязана быть проверяемой: «отступы выглядят странно» не находка, «внутренний зазор карточки 12px равен зазору между карточками 12px, поэтому группа читается одним блоком» — находка. Пустые разделы не выводить; непроверенное перечислять списком в конце.
