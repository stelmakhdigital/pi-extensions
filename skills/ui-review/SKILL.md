# UI Review

Отчёт — только находки. Правила чеклиста пользователю не пересказывать.

## Шаг 0 — контекст и данные

1. Если в проекте есть `DESIGN.md`, читать его и сверять экран с ним: отклонение от токенов = находка, а не «вариант».
2. Наполнить поля данными до проверки. На пустой модели переполнение, обрезка и пустые состояния не видны ничем, кроме глаз, и глаза их не увидят. Минимум: имя 40+ символов, домен/email 30+, число с разделителями и валютой, дата с таймзоной, одно пустое поле, список из 0 / 1 / 12 записей. Если наполнить нечем (нет моков, нет бэкенда) — сказать об этом в отчёте и пометить раздел «Данные» как непроверенный.
3. Открыть состояния, которые не видны по умолчанию: через `--click` (модалка, дропдаун, раскрытие), через URL/состояние приложения или вручную. Ревью одного первого экрана без модалки — не ревью.

## Шаг 1 — машинная проверка

```bash
node "$(dirname "$SKILL_FILE")/scripts/a11y.mjs" http://localhost:3000 \
  --widths 375,768,1440 --out ui-review/run-1 --wait 800
# модалка/меню: --click "button.open-menu,button.new-item"
# регрессия к предыдущему прогону: --baseline ui-review/run-1
# шум сжатия/антиалиасинга сыпется: --diff-threshold 0.2
# CI: --strict  (exit 1 при нарушениях moderate+)
```

Коды выхода: 0 — прогон прошёл, 1 — `--strict` и есть moderate+, 2 — неверные аргументы, 3 — нет playwright, 4 — chromium не запустился (3 и 4 означают «проверку не выполняли», а не «нарушений нет»).

Один раз на проверяемый проект: `npm i -D playwright && npx playwright install chromium`. Без `playwright` скрипт сам скажет, что установить, и выйдет с кодом 3. Для офлайна: `--axe ./node_modules/axe-core/axe.min.js` (иначе axe берётся с CDN). Статичный HTML можно давать как `file://`.

Что скрипт ловит: нарушения axe (роли, имена, контраст, landmarks, `meta viewport`, `tabindex`, `aria-*` на невалидных элементах), горизонтальный скролл и элемент шире вьюпорта, шрифт < 12px, цели клика < 24px, `transition: all`, `will-change`, отсутствие `prefers-reduced-motion` / `prefers-contrast`, `<html lang>`, `user-scalable=no`.

Что скрипт не ловит — для этого шаги 2 и 3: корректность `aria-current`/`aria-expanded`, порядок фокуса, ловушка фокуса в модалке, контраст `disabled` (axe его пропускает), переполнение на надутых данных внутри модалки, иерархия, плотность, выравнивание, пустые/ошибочные состояния, отклонение от `DESIGN.md`.

`--baseline` к предыдущему прогону даёт побитовое сравнение кадров: в отчёте процент и число изменившихся пикселей, рядом с скриншотом лежит `<width>-diff.png`, где изменения залиты красным. Прочитай diff-кадр и разбери, что изменилось; «изменилось 3%» без разбора — не находка. Порог по умолчанию 0.12 (как в pixelmatch), меняется `--diff-threshold`. Разные размеры кадров diff не считают (изменилась высота документа или ширина вьюпорта) — это отдельная находка.

## Шаг 2 — глазами по скриншотам

Смотреть `ui-review/run-N/<width>.png`, а не живой браузер: скриншот фиксирует то, что потом уедет из контекста. По каждой ширине ответить на четыре вопроса:

1. Что первое бросается в глаза и совпадает ли это с главным действием экрана.
2. Где текст режет, прилипает к соседнему блоку или встаёт в одну строку на весь экран.
3. Где блок неопределённой ширины/высоты сядет на сосед при 12 записях вместо 3.
4. Держится ли один визуальный язык (радиусы, тени, отступы, веса) или каждый блок сам по себе.

## Шаг 3 — чеклист

Тяжесть: `blocker` (ломает использование или недоступно), `major` (портит экран заметно), `minor` (косметика).

### Семантика и доступность

- `aria-current="page"` у активного пункта навигации и `aria-current` у активной вкладки/шага; без него «активный» читается только по цвету.
- `aria-expanded` на всём, что раскрывается, плюс `aria-controls` на связь; `<details>` проще и почти всегда достаточен.
- У полей `label` (не `placeholder` вместо него), `aria-describedby` на текст ошибки, `aria-invalid` при ошибке, тип `input` и `inputmode` под данные.
- Асинхронные сообщения (сохрано, ошибка запроса, счётчик результатов) — `aria-live="polite"`, иначе их никто не услышит.
- `disabled` с контрастом >= 4.5:1 или не через opacity: axe проверенный элемент с `disabled` пропускает.
- Клавиатурная альтернатива drag-and-drop: кнопки «выше/ниже», стрелки с модификатором, или меню с действием перемещения. Только мышь = фича недоступна.
- `:focus-visible` не удалён без замены; порядок обхода следует визуальному порядку; в модалке ловушка фокуса и `Esc`; skip-link на экранах с навигацией.
- Не-текстовые кликабельные области >= 24px (на мобильных 44px), цели не слиплись.

### Layout

- `min-width: 0` (и `min-height: 0` в column) у детей flex и grid — типовая причина горизонтального скролла; вместе с `text-overflow: ellipsis` или `line-clamp` там, где строка должна резаться.
- `overscroll-behavior: contain` у модалок, боковых панелей и внутренних скролл-зон, плюс блокировка прокрутки `body`, пока оверлей открыт.
- Высоты: `100dvh` вместо `100vh`, `min-height` вместо фиксированной высоты там, где контент может вырасти.
- `position: sticky` не выпадает под `overflow: hidden` у родителя; `z-index` по шкале, а не 9999/999999.
- Сетки под неизвестное число элементов: `auto-fill/minmax`, а не жёсткое число колонок; вложенность гридов не прячет переполнение.
- `safe-area-inset` на мобильных, отступы не съедаются вырезом экрана и клавиатурой.

### Motion

- Без `transition: all` — перечислять свойства; `will-change` только на том, что действительно анимируется, и снимать после.
- Анимировать `transform`/`opacity`, не `height`/`width`/`top`/`left`.
- `prefers-reduced-motion`: анимации и параллакс выключаются, состояние остаётся читаемым (не `opacity: 0` навсегда).
- Анимация появления не сдвигает контент под ней (layout shift) и не блокирует ввод.

### Состояния и данные

- Loading: скелетон в форме будущего контента, не спиннер посреди пустой страницы; кнопки не допускают двойную отправку.
- Empty: пустое состояние объясняет следующее действие; ошибка — не тот же текст, что пустой список.
- Hover, focus, active, visited — различимы и не завязаны только на цвет; на тач-устройствах hover-подсказок нет.
- Длинные строки, нули и пустые значения, отрицательные числа, `+999 999 999 ₽`, даты с таймзоной, одна запись и двенадцать.
- Тексты кнопок — глагол и ожидаемое действие; «Подробнее»/«Отправить» без контекста = находка.

### Ответ пользователю

```
src/InvoiceTable.tsx:118 — blocker — ячейка суммы вылезает за вьюпорт на 375: у td нет min-width: 0, добавь min-width: 0 + text-overflow
DOM button.icon (375px) — major — цель 20x20px, поднять до 44px псевдоэлементом
ui-review/run-1/768.png — minor — заголовок карточки прилип к бейджу, добавить gap 8px
```

Селекторы из браузера помечать как `DOM ...` с шириной, файловую строку указывать, когда причина в коде. Если по разделу находок нет — раздел не выводить. Отличия скриншотов и непроверенные разделы (нет данных, не открыта модалка) перечислить отдельным списком в конце.
