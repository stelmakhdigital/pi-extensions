# UI Dashboard

Экран с данными оценивается по одному критерию: за сколько секунд находится ответ на вопрос. Красота вторична, плотность и сравнимость первичны. Визуальный язык и токены — в `../ui-design/SKILL.md`, проверка готового экрана — в `../ui-review/SKILL.md`, скорость — в `../frontend-perf/SKILL.md`.

## Шаг 0 — вопрос, на который экран отвечает

Одна строка перед сборкой: «кто и какой вопрос задаёт этому экрану» («куда ушёл бюджет в этом месяце», «какие сервисы деградируют»). Экран, где на этот вопрос отвечает один блок, а не двенадцать карточек с цифрами, — уже половина результата.

Если в проекте есть `DESIGN.md`, токены и шкала отступов берутся оттуда; для данных отдельно фиксируется шкала размера цифр (см. шаг 3).

## Шаг 1 — форма по типу вопроса

| Вопрос | Форма | Не делать |
|---|---|---|
| Как менялось во времени | линейный график, 1-3 серии | области с прозрачной заливкой на 5 сериях |
| Сколько сейчас, важно сравнение с прошлым | крупная цифра + дельта + спарклайн | круговая диаграмма |
| Из чего состоит сумма | stacked bar горизонтально или таблица с долями | pie на 9 секторов |
| Кто первый, рейтинг | горизонтальные бары, сортировка по значению | вертикальные бары с подписями под 45° |
| Распределение | box plot или гистограмма | среднее без разброса |
| Зависимость двух величин | scatter с регрессией, если она есть | две таблицы рядом |
| Состав по категориям + числа | таблица с условным оформлением ячеек | график без таблицы, когда числа сравниваются построчно |
| Где (карта) | карта только если география меняет решение | карта ради красоты |

Детали: выбор типа, оси, форматтеры и состояния — в `references/charts.md`.

## Шаг 2 — данные прежде макета

Верстать на надутых и на вырожденных данных, обе проверки до сдачи:

- Надутые: имя 40+ символов, число `1 284 903,57 ₽`, дата с таймзоной, 5 000 строк в таблице, 1280/768/375.
- Вырожденные: 0 строк, 1 точка на графике, все нули, отрицательные значения, один спайк на порядок выше остальных, пропуски в середине ряда, значения без прав доступа (`—`, не `0`).

Каждая из вырожденных ситуаций имеет названное поведение, иначе экран разваливается на первом же реальном запросе. Шаблоны реакций — в `references/charts.md`, раздел «Вырожденные данные».

## Шаг 3 — числа читаются, а не выглядят

- Разделители тысяч по локали, валюта и единица в заголовке или один раз у значения, но не в каждой ячейке.
- Компакт (`1,2 млн`) допустим в заголовке карточки и в подписи оси; в таблице — точное значение.
- Дельта со знаком и направлением: `+12%` и стрелка (или цвет) плюс текст для скринридера; цвет alone не несёт смысл (красный/зелёный не различаются при дальтонизме).
- Один формат на колонку. `12,5` рядом с `12,50` и `12` в одной колонке читается как ошибка данных.
- Оси: ноль на шкале частоты обязателен, у денежной шкалы ноль обязателен только если сравниваются величины, иначе подписать обрезку. Метки на 2-3 меньше, чем позволяют пиксели: подписи осей не должны конкурировать с линиями.
- Цвет: один акцент на ряд, последовательная шкала для величины, расходящаяся для «вокруг нуля». Радуга и 8 цветов легенды — признак, что ряды не разобраны.

## Шаг 4 — состояния и плотность

- Состояния на каждый блок данных: загрузка (скелетон тех же размеров), пусто (что делать, а не «нет данных»), ошибка (причина + повтор), частично (половина серий не пришла — сказать, а не рисовать неполный график как истину), нет прав (`—` с объяснением).
- Таблица: липкая шапка при скролле корпуса, сортировка с `aria-sort`, нумерация и «показано X из Y», строчка-детали на клик, горизонтальный скролл корпуса вместо сплющивания колонок.
- Фильтры и выбранный период — в URL: экран должен открываться по ссылке и переживать перезагрузку.
- Плотность: цифры выравниваются по правому краю, текст по левому; вертикальные разделители между колонками не нужны, когда есть выравнивание.
- Автообновление: показывать «обновлено 14:03» и паузу на ховере, иначе сравнение двух чисел в разных моментах времени врёт.

## Шаг 5 — проверка

- `a11y.mjs <url> --out DIR` на 375/768/1440 надутыми данными: разделы про переполнение, тесные цели, `aria-sort` и картинки. Скриншоты показать, а не описать.
- `perf.mjs <url> --wait 1500` — на списке в тысячу строк типичны длинные задачи; `TBT > 200 мс` = виртуализировать или резать на страницы.
- Миниатюрой (375px) проверить, не превратился ли график в кашу: на мобильном чаще правильны 1-2 метрики и таблица, чем шесть графиков.
- Проверить чтение вслух: зачитать заголовок карточки и значение скринридером — из `+12%` и `—` должно быть понятно направление и смысл пропуска.
